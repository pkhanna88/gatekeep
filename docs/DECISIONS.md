# Decision log

Every significant decision, recorded when it is made. New joiners and
occasionally customers need the reasoning.

| Date | Decision | Reasoning | Revisit when |
|---|---|---|---|
| Prebuild | Python over Go | Team fluency; four engineers learning identity should not also learn a language | High-volume deal needs sub-10ms |
| Prebuild | SPIRE deferred | ~1 week of 25; no first-demo buyer asks for attestation | Phase 2, or first customer who asks |
| Prebuild | ReBAC via OpenFGA | Only model that expresses per-record authority without role explosion | Never — this is core |
| Prebuild | 5-minute token TTL | Makes revocation tractable; defence in depth beyond the PEP | If refresh traffic becomes a bottleneck |
| Prebuild | Salesforce as connector one | Recognisable to buyers; free dev org | Day 2 gate if spike overruns |
| Prebuild | Advisory lock on audit writes | Prevents chain forking under concurrency; survives multiple instances | If audit write throughput becomes a bottleneck |

| Day 1 | OpenFGA uses the in-memory store | Skips a migration step; `make seed` is the source of truth anyway | When tuples need to survive a restart |
| Day 1 | OpenFGA pinned to v1.14.0 | `latest` changes under us. v1.14.0 is also the first release fixing CVE-2026-40293 (playground leaked a preshared key in HTML). We do not use preshared auth so were not exposed, but pin to a patched floor anyway | Bump deliberately; check the changelog first |
| Day 1 | ~~Playground bound to 0.0.0.0~~ | Superseded — see the playground row below. The binding was correct; the tool is not usable regardless | — |
| Day 1 fix | The principal identifier is the `principal` claim, never `sub` | Keycloak's `sub` is an opaque UUID, but every FGA tuple, `grants.principal_sub` and the §6.3 token are written as emails, so §7.1's approver check could never have matched — it would have read as a policy bug rather than a realm one. Forcing `sub` to the email fixes it locally and breaks §3.3's promise that swapping to Okta or Entra is configuration, not code, since their `sub` is a UUID too. A dedicated claim means changing IdP is remapping one field | Never, unless a customer IdP cannot mint a custom claim |
| Day 1 fix | Console tokens carry `aud: gatekeep-control-plane` | §4.4 lists audience as something we verify at the Human → Console boundary, and tokens were arriving with no `aud` at all. BE1 cannot gate approvals on a claim that is not there | When a second API starts accepting human tokens |
| Day 1 fix | OpenFGA listens on 8081/8082 inside the container, matching the published ports | OpenFGA advertises its own address to clients, derived from the port it listens on **inside** the container. The mapping `8081:8080` therefore told browsers to call `127.0.0.1:8080` — Keycloak on the host. Keeping inside and outside identical means anything OpenFGA says about where to reach it is also true from the host | If the handbook's §3.10 port assignments change |
| Day 1 fix | Built-in OpenFGA playground disabled | It is a page wrapping an iframe to the remote site play.fga.dev, and every browser now blocks a public page from reaching the loopback address space — verified on Chrome, WebKit and Firefox. Not fixable from our side: a proxy sending the documented opt-in header `Access-Control-Allow-Private-Network: true` was tested and all three still refused, so browsers have moved past header-based opt-in to blocking outright. It is deprecated upstream and hands the API token to a third party in a URL. No other role's work changes this | If OpenFGA ships a first-party local playground |
| Day 7 | Child record types stay separate, not collapsed into one `record` type | Resolves Day 2 model review question 1. §5.3 puts the resource type in the scope string and §7.1/§7.2 build the FGA object straight from it. One type per scope type keeps that a concatenation instead of a lookup table on the enforcement path. Auditors also ask “who can view invoices” directly. Cost is three mechanical blocks | If a fifth and sixth record type arrive and the duplication starts hiding bugs |
| Day 7 | `make seed` verifies, and fails, rather than just loading | Loading a model proves nothing; it has to answer correctly, including saying no. `deploy/seed/fga-checks.json` is Day 3's “verified by hand in the playground” written down so it runs in CI. Six of the eleven checks must come back False | Never — if the matrix gets slow, page it, do not delete it |
| Day 7 | `kid` derives from the OpenBao transit key version (`gk-signing-v1`) | §3.5 warns that retrofitting kid-based key selection is unpleasant, and transit already versions keys and keeps old versions verifiable after a rotate. Deriving `kid` mechanically means JWKS publication and rotation need no separate bookkeeping. The handbook's `gk-2026-08` style is cosmetic and does not map to a key version | If we ever sign with something other than transit |
| Day 7 | **Decision gate: connector one is the mock. Salesforce → Phase 2** | The Day 2 gate, made on Day 7. The spike was never started — BE2 unstaffed — so we are choosing on absence of evidence, which is exactly what the gate is for. §8.4 lists the Salesforce connector as the second thing to cut and never as a thing to protect; none of the five never-cut items depend on it. Full reasoning in docs/CONNECTOR-NOTES.md | A named buyer asks for a live Salesforce demo, or BE2 is staffed and Week 2 exits early with real slack |
| Day 7 | Created a `gatekeep_app` Postgres role; services never connect as the owner | §5.1 says to REVOKE UPDATE and DELETE from `gatekeep_app`, but no such role existed — compose creates one superuser and services would have connected as it. Revoking from a superuser does nothing: superusers bypass permission checks and table owners keep their rights. The append-only guarantee was decoration until the role existed | Never — if a service needs UPDATE on audit_events, the design is wrong |
| Day 7 | `reason` stays outside the audit hash, matching §5.4 exactly | §5.4's canonical form covers eleven fields and omits `reason`, so a denial's stated reason can be edited without breaking the chain. Deviating locally would make our exports unverifiable by any other implementation of the documented algorithm — worse than the gap. Recorded in docs/SECURITY.md §8.3 and pinned by a test | When closing it is worth a canonical-form change, re-hashing existing entries, and a second reviewer |
| Day 7 | `make migrate` gets a raw-SQL stand-in until alembic lands | Day 4's audit chain cannot be written, run or tested against a table that does not exist, and BE1's Day 1 migration has not happened. Thirty lines applying ordered .sql files, clearly labelled, so it is obvious what to delete rather than something that quietly becomes a migration framework | The moment BE1 wires alembic — fold 0001 in as the initial revision and delete the stand-in |
| Day 7 | ARCHITECTURE / SECURITY / CONNECTOR-NOTES moved to `docs/` | §4.6 and the README's own layout section both put them under docs/, and Day 5's task literally reads `docs/SECURITY.md`. The repo contradicted itself and Appendix A's paths were wrong. GitHub still finds a security policy at docs/SECURITY.md | Never |
